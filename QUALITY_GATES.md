# QUALITY_GATES.md: Checkpoint Verification, Evaluation Matrix & Rollback Protocols

## 1. Quality Philosophy: Zero Regressions & 95%+ First-Attempt Success

The primary root cause of the "AI Whack-A-Mole" problem is the absence of **deterministic, multi-dimensional verification barriers** between agent actions. In standard coding agents, code generated by one step is assumed to be correct and immediately injected into the context of the next step. If that code contains a subtle type mismatch, a security vulnerability, or breaks an existing contract, the subsequent agent builds upon a compromised foundation, triggering a compounding failure loop.

This architecture enforces **Zero-Trust Layered Quality Gates**. No task artifact, code modification, schema definition, or configuration file may transition across a domain or layer boundary without satisfying cryptographically verifiable, automated acceptance criteria.

## 2. The 7 Layered Quality Checkpoints

The development lifecycle is partitioned by seven mandatory Quality Gates ($QG\text{-}1$ through $QG\text{-}7$).

```
[User Request]
       |
       v
+--------------+
|     QG-1     | -> Intent & Spec Gate (Validates constraints, requirements, inputs/outputs)
+--------------+
       | Passed
       v
+--------------+
|     QG-2     | -> Architecture & Interface Contract Gate (Validates OpenAPI, schemas, DAG)
+--------------+
       | Passed
       v
+--------------+
|     QG-3     | -> Syntactic & Atomic Hygiene Gate (AST valid, typing clean, linters pass)
+--------------+
       | Passed
       v
+--------------+
|     QG-4     | -> Verification & Test Gate (Unit tests 100% green, 90%+ coverage, 0 regressions)
+--------------+
       | Passed
       v
+--------------+
|     QG-5     | -> Security & Compliance Gate (SAST clean, 0 secret leaks, OWASP pass)
+--------------+
       | Passed
       v
+--------------+
|     QG-6     | -> Performance & Resource Gate (<=512MB RAM, <=4096 tok/req, <=30s latency)
+--------------+
       | Passed
       v
+--------------+
|     QG-7     | -> Final Integration & Deployment Gate (Clean git tree, container/build pass)
+--------------+
       | Passed
       v
[Production State Commit & Delivery]
```

### Detailed Quality Gate Specifications

| Gate ID | Designation | Evaluating Agent | Automated Verification Criteria | Hard Failure Condition |
| :--- | :--- | :--- | :--- | :--- |
| **QG-1** | **Intent & Specification** | `SPEC_001` / `PLAN_001` | - Unambiguous functional requirements.<br>- Declared inputs, outputs, and types.<br>- Bounded scope (no open-ended tasks). | Unresolved user ambiguity; missing output types. |
| **QG-2** | **Interface Contract** | `ARCH_001` / `DEC_001` | - OpenAPI/JSON-Schema syntax valid.<br>- Database ERD relationships normalized.<br>- Task DAG is strictly acyclic (0 cycles). | Cyclic dependency in DAG; schema validation error. |
| **QG-3** | **Syntactic & Atomic** | `L7_VAL_xx` / `DEV_001` | - Python AST parsed with 0 syntax errors.<br>- Mypy strict type checking pass.<br>- Ruff/Flake8 0 linting warnings. | AST syntax error; type mismatch; unformatted code. |
| **QG-4** | **Verification & Test** | `UTEST_001` / `TEST_001` | - 100% of newly written tests pass.<br>- 100% of existing regression suite passes.<br>- Code coverage on new lines $\ge 90\%$. | Any failed test; regression detected; coverage $<90\%$. |
| **QG-5** | **Security & Compliance** | `SAST_001` / `SEC_001` | - Bandit SAST scan: 0 High / 0 Medium findings.<br>- Secret detector: 0 API keys/passwords in diff.<br>- OWASP Top 10 rule check passed. | Any hardcoded secret; SQL injection risk; unescaped output. |
| **QG-6** | **Performance & Resource**| `TEL_001` / `MON_001` | - Agent peak RAM $\le 512\,\text{MB}$.<br>- Task execution duration $\le 30\,\text{seconds}$.<br>- Prompt token usage $\le 4,096\,\text{tokens}$. | OOM trigger; timeout $>30\text{s}$; context saturation. |
| **QG-7** | **Final Integration** | `ORCH_001` / `DEP_001` | - Clean git working tree (`git status --porcelain` empty).<br>- Integration test suite 100% green.<br>- Production build/package exit code 0. | Dirty untracked files; broken build; container failure. |

## 3. Multi-Dimensional Evaluation Matrix

A holistic evaluation metric combines four orthogonal dimensions into a unified **Quality Index ($Q_{\text{total}}$)**:

$$Q_{\text{total}} = 0.40 \cdot Q_{\text{correctness}} + 0.25 \cdot Q_{\text{security}} + 0.20 \cdot Q_{\text{maintainability}} + 0.15 \cdot Q_{\text{performance}}$$

```
+-------------------------------------------------------------------------+
|                  MULTI-DIMENSIONAL EVALUATION RADAR                     |
|                                                                         |
|                          CORRECTNESS (40%)                              |
|                              Target: >=95%                              |
|                                    ^                                    |
|                                    |                                    |
|             MAINTAINABILITY (20%)  |  SECURITY (25%)                    |
|             Target: >=90%          |  Target: >=95%                     |
|                   \                |                /                   |
|                    \               |               /                    |
|                     <--------------+-------------->                     |
|                                    |                                    |
|                                    |                                    |
|                                    v                                    |
|                            PERFORMANCE (15%)                            |
|                              Target: >=85%                              |
+-------------------------------------------------------------------------+
```

### Evaluation Metric Formulas

#### 1. Correctness Score ($Q_{\text{correctness}}$)
$$Q_{\text{correctness}} = \left(\frac{T_{\text{passed}}}{T_{\text{total}}}\right) \times 0.70 + \left(\min\left(1.0, \frac{\text{Coverage}}{0.90}\right)\right) \times 0.30$$
* Target: $\ge 95\%$. Hard gate: 100% test pass required ($T_{\text{passed}} = T_{\text{total}}$).

#### 2. Security Score ($Q_{\text{security}}$)
$$Q_{\text{security}} = \max\left(0.0, 1.0 - (0.50 \cdot N_{\text{critical}} + 0.25 \cdot N_{\text{high}} + 0.10 \cdot N_{\text{medium}} + 1.0 \cdot N_{\text{secrets}})\right)$$
* Target: $\ge 95\%$. Hard gate: $N_{\text{critical}} = 0$, $N_{\text{high}} = 0$, $N_{\text{secrets}} = 0$.

#### 3. Maintainability Score ($Q_{\text{maintainability}}$)
$$Q_{\text{maintainability}} = \left(\frac{\text{LintScore}}{10.0}\right) \times 0.50 + \left(1.0 - \min\left(1.0, \frac{\max(0, CC - 10)}{10}\right)\right) \times 0.50$$
Where $CC$ is the cyclomatic complexity of newly generated functions.
* Target: $\ge 90\%$ (Ruff/Flake8 score $\ge 9.5$, $CC \le 10$).

#### 4. Performance Score ($Q_{\text{performance}}$)
$$Q_{\text{performance}} = \left(1.0 - \min\left(1.0, \frac{\text{Latency}_{\text{ms}}}{30000}\right)\right) \times 0.50 + \left(1.0 - \min\left(1.0, \frac{\text{RAM}_{\text{MB}}}{512}\right)\right) \times 0.50$$
* Target: $\ge 85\%$.

## 4. Automated Approval Workflows & Thresholds

```
[Quality Gate Evaluator]
           |
           v
  { Compute Q_total }
           |
     +-----+------------------------------+
     |                                    |
  Q_total >= 0.90                      Q_total < 0.90
 (All Hard Gates = Pass)              (Or Any Hard Gate = Fail)
     |                                    |
     v                                    v
[STATUS: GREEN]                      [STATUS: RED]
     |                                    |
[Create Git Checkpoint]              [Attempt Count <= 2?]
[Commit State to /state/]            |                  |
[Trigger Next Phase in DAG]         YES                 NO
                                     |                  |
                                     v                  v
                            [STATUS: AMBER]      [ESCALATE TO PARENT]
                            [Isolated Retry]     [Trigger Rollback]
                            [Inject Feedback]    [Halt Pipeline]
```

### Gate Decision Logic:
- **GREEN ($\ge 90\%$ and all hard constraints met):** Immediate automated approval. State engine commits a new snapshot to `/state/checkpoints/` and releases dependent downstream tasks.
- **AMBER ($<90\%$ on first attempt with soft failure, e.g., missing docstring or minor typing error):** An automated feedback prompt containing the compiler/linter error is injected into the same atomic agent for one corrective iteration.
- **RED ($<90\%$ on second attempt, or any hard constraint violated, e.g., security leak or regression break):** Immediate automated rejection. No code is merged. Rollback procedure triggers immediately.

## 5. Rollback Procedures & Idempotent Workspace Restoration

When a Quality Gate emits a `RED` status, the system executes an automated, four-step restoration protocol to guarantee tool state hygiene:

```
[RED Gate Detected on Task TSK_XYZ]
                 |
                 v
+-------------------------------------------------------------+
| STEP 1: Process Quarantine & Termination                   |
| - Send SIGTERM/SIGKILL to worker PID.                       |
| - Mark agent registry status = 'failed'.                    |
| - Trip circuit breaker to 'OPEN'.                           |
+-------------------------------------------------------------+
                 |
                 v
+-------------------------------------------------------------+
| STEP 2: Git Working Tree Rewind                             |
| - Read git_commit_sha from last green checkpoint metadata.  |
| - Execute: git reset --hard <git_commit_sha>                |
| - Execute: git clean -fd                                    |
| (Workspace restored to 100% clean pre-task state)          |
+-------------------------------------------------------------+
                 |
                 v
+-------------------------------------------------------------+
| STEP 3: State & Blackboard Purge                            |
| - Remove task TSK_XYZ from /state/tasks/active/             |
| - Evaporate any unverified pheromone traces from blackboard.|
| - Revert task status in task_dag.json to 'FAILED'.          |
+-------------------------------------------------------------+
                 |
                 v
+-------------------------------------------------------------+
| STEP 4: Parent Decomposition Escalation                     |
| - Bubble FailureReceipt up to supervising parent agent.     |
| - Parent chooses: alternate agent OR template fallback.     |
+-------------------------------------------------------------+
```

## 6. Success Metrics Tracking Table

Every executed mission is benchmarked against these formal system-level Service Level Objectives (SLOs):

| Metric | Target Objective | Measurement Mechanism | Enforcement Mechanism |
| :--- | :--- | :--- | :--- |
| **First-Attempt Success** | $\mathbf{\ge 95\%}$ | Ratio of tasks passing QG-4 on first attempt without retry. | Fractal atomic decomposition + strict specialization. |
| **User Satisfaction** | $\mathbf{\ge 4.8 / 5.0}$ | User acceptance and verification rating. | Complete requirements alignment via QG-1. |
| **Iterations Needed** | $\mathbf{\le 2}$ | Retry count per atomic task before gate passage. | Hard circuit breaker trip at attempt count = 2. |
| **Token Efficiency** | $\mathbf{\le 5000\text{ tokens}}$ | Total system-wide token sum across all agent prompts. | Stigmergy blackboard + artifact offload engine. |
| **Response Time** | $\mathbf{\le 30\text{ seconds}}$ | End-to-end wall-clock latency for single atomic task. | 30-second watchdog thread terminating unresponsive tasks. |
| **Memory Usage** | $\mathbf{\le 8\text{GB RAM}}$ | System-wide RSS consumption across all processes. | 512MB hard limit per agent container/process. |
| **Code Quality Score** | $\mathbf{\ge 90\%}$ | Composite multi-dimensional quality index ($Q_{\text{total}}$). | Mandatory passage of QG-3 and QG-5 before commit. |
| **Test Coverage** | $\mathbf{\ge 90\%}$ | Line and branch coverage reported by `pytest-cov`. | QG-4 automated rejection if coverage $<90\%$. |
